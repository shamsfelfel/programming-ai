One Type, Many Numbers: the Arrayنوعٌ واحد وأعداد كثيرة: المصفوفة

By the end of this lesson you will take a loop that adjusts every mark in a class, watch the obvious list version do something absurd instead, and replace the whole loop with one line. Then you will find out what an array gave up in exchange: a list holds anything, an array holds exactly one type, and that type will quietly change your numbers if you let it.

بنهاية هذا الدرس ستأخذ حلقةً تعدّل كل علامة في صفّ، وسترى نسخةَ القائمة البديهية تفعل شيئًا عبثيًا بدلًا من ذلك، ثم تستبدل بالحلقة كلها سطرًا واحدًا. ثم ستكتشف ما تخلّت عنه المصفوفة في المقابل: فالقائمة تحمل أي شيء، والمصفوفة تحمل نوعًا واحدًا بالضبط، وذلك النوع سيغيّر أرقامك بصمت إن تركته.

Before you startقبل أن تبدأ

This is the first lesson of a new chapter and it assumes only Python lists and loops. The one thing to read first is Appendix A4, on what int64 and float64 actually are — this lesson puts a type on every array you make and the three lessons after it keep referring to it. The patterns of Chapter 2 are not needed here, though the same fit/transform steps reappear in Lesson 13 operating on arrays instead of lists.

هذا أول درس في فصل جديد ولا يفترض إلا قوائم بايثون وحلقاتها. والشيء الوحيد الذي تقرأه أولًا هو الملحق A4، عن ماهية int64 وfloat64 فعلًا — فهذا الدرس يضع نوعًا على كل مصفوفة تصنعها وتظل الدروس الثلاثة بعده تشير إليه. ولا تلزم أنماطُ الفصل 2 هنا، وإن كانت خطوات fit/transform نفسها تعود في الدرس 13 عاملةً على مصفوفات بدل قوائم.

The settingالإطار

The same secondary school as Chapter 2. The leaving class sat three subjects, and the marks now have to be adjusted, summarised and compared. There are thirty students here; by Lesson 13 the same code will be running over far more.

المدرسة الثانوية نفسها من الفصل 2. فقد امتحن صفُّ التخرج في ثلاث مواد، وعلى العلامات الآن أن تُعدَّل وتُلخَّص وتُقارَن. وثمّة ثلاثون طالبًا هنا؛ وبحلول الدرس 13 سيعمل الكود نفسه على أكثر من ذلك بكثير.

Concept 1 — An array does arithmetic; a list does notالمفهوم 1 — المصفوفة تحسب؛ والقائمة لا

The problemالمشكلة

The ministry adds five marks to every paper. You have the marks in a list, and the obvious thing to write does not do the obvious thing.

تضيف الوزارة خمس علامات إلى كل ورقة. والعلامات عندك في قائمة، والشيءُ البديهي الذي تكتبه لا يفعل الشيء البديهي.

The starting codeالكود الابتدائي

marks = [40, 55, 70, 85, 100]

print(marks + 5)
TypeError: can only concatenate list (not "int") to list

Fair enough — + on a list means "join another list on the end", so adding a number is meaningless. Try doubling instead, where * is defined:

لا بأس — فـ + على قائمة تعني «ألحِق قائمة أخرى في النهاية»، فإضافةُ عدد بلا معنى. جرّب المضاعفة بدلًا من ذلك، حيث * معرَّفة:

print(marks * 2)
[40, 55, 70, 85, 100, 40, 55, 70, 85, 100]

Diagnosisالتشخيص

This one is worse than the error, because it worked. marks * 2 did not double thirty marks; it produced sixty marks. A class of thirty is now a class of sixty, every student appears twice, and the average is unchanged so the mistake is invisible in a summary. The first version at least refused.

هذه أسوأ من الخطأ، لأنها نجحت. فـ marks * 2 لم تضاعف ثلاثين علامة؛ بل أنتجت ستين علامة. فصارَ صفُّ الثلاثين صفَّ ستين، وظهر كل طالب مرتين، والمتوسط لم يتغير فصار الخطأ غير مرئي في أي ملخّص. والنسخة الأولى رفضت على الأقل.

Name the defectسمِّ العيب

A list is a container, so its operators are container operations: join and repeat. You wanted arithmetic on every element, and a list has no idea that is what its contents are for. The usual answer is a loop:

القائمة حاوية، فعملياتها عمليات حاويات: الإلحاق والتكرار. وأنت أردت حسابًا على كل عنصر، والقائمةُ لا تدري أن ذلك ما محتواها له. والجواب المعتاد حلقة:

adjusted = []
for m in marks:
    adjusted.append(m + 5)
print(adjusted)
[45, 60, 75, 90, 105]

Correct, and four lines. Now do it for three subjects, then scale them, then centre them, and the file fills up with loops that all say the same thing in slightly different words.

صحيح، وأربعة أسطر. والآن افعلها لثلاث مواد، ثم قِسها، ثم مركِزها، فيمتلئ الملف بحلقات تقول الشيء نفسه بكلمات مختلفة قليلًا.

Conversion — a container that knows it holds numbersالتحويل — حاوية تعلم أنها تحمل أعدادًا

import numpy as np

marks = np.array([40, 55, 70, 85, 100])

print(marks + 5)
print(marks * 2)
print(marks / 100)
print(marks > 60)
[ 45 60 75 90 105] [ 80 110 140 170 200] [0.4 0.55 0.7 0.85 1. ] [False False True True True]

Every operator now means "do this to each element and give me an array of the answers". The loop is gone, and so is the chance of writing it wrongly. The last line is worth a second look: comparing an array to a number gives an array of True and False, one per mark, which is the basis of everything in Lesson 13.

صار كل معامل يعني «افعل هذا بكل عنصر وأعطني مصفوفة الأجوبة». فاختفت الحلقة، واختفت معها فرصةُ كتابتها خطأً. والسطر الأخير يستحق نظرة ثانية: فمقارنة مصفوفة بعدد تعطي مصفوفة True وFalse، واحدةً لكل علامة، وهي أساس كل ما في الدرس 13.

Why this is also much fasterولماذا هذا أسرع كثيرًا أيضًا

A Python loop over a million marks executes a million separate Python steps. marks + 5 hands the whole array to compiled code that walks the memory once. The speed is the famous part, but it is the second reason to use an array; the first is that one line cannot be written wrongly in six different places.

حلقةُ بايثون على مليون علامة تنفّذ مليون خطوة بايثون منفصلة. أما marks + 5 فتسلّم المصفوفة كلها إلى كود مترجَم يمشي في الذاكرة مرة واحدة. والسرعة هي الجزء الشهير، لكنها السبب الثاني لاستعمال المصفوفة؛ والأول أن سطرًا واحدًا لا يمكن كتابته خطأً في ستة مواضع مختلفة.

What does this print?
a = np.array([1, 2, 3])
a[0] = 2.9
print(a)ماذا يطبع هذا؟
a = np.array([1, 2, 3])
a[0] = 2.9
print(a)

Cut, not rounded: the decimal part is thrown away, so 2.9 becomes 2 and 2.99 would too. And the array does not change its mind about its type — it was decided when the array was built, which is why the second option is wrong in a more interesting way than the first. If the marks might have decimals, say so at build time: np.array([1, 2, 3], dtype=float).
قطعٌ لا تقريب: فالجزء العشري يُرمى، فتصير 2.9 اثنين، وكذلك 2.99. ولا تغيّر المصفوفة رأيها في نوعها — فقد قُرِّر عند بنائها، ولذلك كان الخيار الثاني خاطئًا بوجه أطرف من الأول. فإن كانت العلامات قد تحمل عشريات فقل ذلك عند البناء: np.array([1, 2, 3], dtype=float).

Exercise 10.1 — Reserve the table before the marks existتمرين 10.1 — احجز الجدول قبل وجود العلامات

Thirty students will sit four papers, and no mark has been entered yet. Build the empty table, print its shape, ndim, size and dtype, then enter one mark of 72.5 for the first student’s first paper and print that student’s row.

ثلاثون طالبًا سيقدّمون أربع أوراق، ولم تُدخَل علامةٌ بعد. ابنِ الجدول الفارغ واطبع shape وndim وsize وdtype، ثم أدخِل علامة 72.5 لأول ورقةٍ لأول طالب واطبع صفّ ذلك الطالب.

students = 30
# build the table here
# expected: (30, 4) 2 120 float64
Show solutionإظهار الحل 
table = np.zeros((students, 4))
print(table.shape, table.ndim, table.size, table.dtype)

table[0, 0] = 72.5
print(table[0])
(30, 4) 2 120 float64 [72.5 0. 0. 0. ]

The shape goes in as one tuple, because the second argument of np.zeros is the dtype — np.zeros(30, 4) is an error. Now try the same thing with np.zeros((30, 4), dtype=int): the 72.5 is stored as 72, with nothing to warn you. An empty table reserved with the wrong type quietly damages every value written into it afterwards, which is why this is the moment to decide.

الشكلُ يدخل صفًّا (tuple) واحدًا، لأن الوسيط الثاني لـ np.zeros هو النوع — فـ np.zeros(30, 4) خطأ. وجرّب الآن الشيء نفسه بـ np.zeros((30, 4), dtype=int): فتُخزَّن 72.5 وهي 72 بلا ما يحذّرك. فالجدولُ الفارغ المحجوز بالنوع الخاطئ يُتلف بصمتٍ كل قيمة تُكتب فيه بعد ذلك، ولذلك كانت هذه لحظةَ القرار.

Note that 0.0 is a real mark, not a blank. A table of zeros says every student scored nothing; a table that means “not marked yet” needs np.nan, which arrives in Lesson 13.

ولاحظ أن 0.0 علامةٌ حقيقية لا فراغ. فجدولُ الأصفار يقول إن كل طالب لم ينل شيئًا؛ وأما الجدول الذي يعني «لم يُصحَّح بعد» فيحتاج np.nan، وهي تصل في الدرس 13.

Concept 2 — What an array gave up: one type for everythingالمفهوم 2 — ما تخلّت عنه المصفوفة: نوعٌ واحد للجميع

The arithmetic is not free. A list can hold a number, a string and another list at once; an array decides on one type when it is built and applies it to every value, for ever.

الحساب ليس مجانًا. فالقائمة تحمل عددًا ونصًّا وقائمة أخرى معًا؛ والمصفوفة تقرّر نوعًا واحدًا عند بنائها وتطبّقه على كل قيمة إلى الأبد.

whole = np.array([40, 55, 70])
print(whole, whole.dtype)

decimal = np.array([40, 55, 70.5])
print(decimal, decimal.dtype)

mixed = np.array([1, "two", 3])
print(mixed, mixed.dtype)
[40 55 70] int64 [40. 55. 70.5] float64 ['1' 'two' '3'] <U21

Three different decisions, none of them announced. All whole numbers gives int64. One decimal among them promotes every value to float64 — notice 40. with a trailing dot. And one string turns the numbers into text: <U21 means "unicode string, up to 21 characters", and mixed * 2 would now repeat the text rather than double anything.

ثلاثة قرارات مختلفة، لم يُعلَن أيٌّ منها. فالأعداد الصحيحة كلها تعطي int64. وعشريٌّ واحد بينها يرفع كل قيمة إلى float64 — لاحظ 40. بالنقطة اللاحقة. ونصٌّ واحد يحوّل الأعداد كتابةً: فـ <U21 تعني «نص يونيكود حتى 21 محرفًا»، وستكرّر mixed * 2 النصَّ الآن بدل مضاعفة أي شيء.

The trap: an integer array silently truncatesالفخ: مصفوفة الأعداد الصحيحة تبتر بصمت

marks = np.array([40, 55, 70])
print(marks.dtype)

marks[0] = 2.9
print(marks)
int64 [ 2 55 70]

2.9 went in and 2 came out. The array is int64, it has nowhere to put a fraction, and it does not consider that worth mentioning. Scale an integer array by 0.9 and assign the result back into it and every mark loses its decimal part, quietly, for every student. The fix is to decide the type when you build it:

دخلت 2.9 وخرجت 2. فالمصفوفة int64، ولا موضع فيها لكسر، ولا ترى ذلك جديرًا بالذكر. وقِس مصفوفةَ أعداد صحيحة بـ 0.9 وأسند النتيجة إليها يفقد كلُّ علامة جزأها العشري، بصمت، لكل طالب. والإصلاح أن تقرّر النوع عند البناء:

marks = np.array([40, 55, 70], dtype=float)
marks[0] = 2.9
print(marks, marks.dtype)
[ 2.9 55. 70. ] float64

Shape: the same numbers, arrangedالشكل: الأعداد نفسها، مرتّبةً

The class sat three subjects, so the natural arrangement is a table: one row per student, one column per subject.

امتحن الصفُّ في ثلاث مواد، فالترتيب الطبيعي جدول: صفٌّ لكل طالب وعمودٌ لكل مادة.

marks = np.array([[40, 55, 70],
                  [60, 65, 90],
                  [80, 75, 50]])

print(marks.shape)
print(marks.ndim)
print(marks.size)
print(marks.dtype)
(3, 3) 2 9 int64
  • shape is (rows, columns) — always that order, and it is a tuple, so a 1-D array of five marks has shape (5,) with the comma and nothing after it.shape هو (الصفوف، الأعمدة) — بهذا الترتيب دائمًا، وهو صفٌّ (tuple)، فمصفوفة أحادية بخمس علامات شكلها (5,) بالفاصلة ولا شيء بعدها.
  • ndim is how many dimensions: 1 for a row of marks, 2 for a table.ndim هو عدد الأبعاد: 1 لصفّ علامات، و2 لجدول.
  • size is how many numbers in total, which is every dimension multiplied together.size هو عدد الأعداد كلها، وهو حاصل ضرب كل الأبعاد.

Arithmetic works on the table exactly as it did on the row, element by element, with no loops and no nesting:

والحساب يعمل على الجدول تمامًا كما عمل على الصفّ، عنصرًا عنصرًا، بلا حلقات ولا تعشيش:

print(marks + 5)
print(marks.shape, (marks + 5).shape)
[[ 45 60 75] [ 65 70 95] [ 85 80 55]] (3, 3) (3, 3)

Making arrays without typing every numberصنع المصفوفات دون كتابة كل عدد

print(np.zeros(3))
print(np.ones((2, 3)))
print(np.full((2, 2), 7))
print(np.arange(0, 10, 2))
print(np.linspace(0, 1, 5))
[0. 0. 0.] [[1. 1. 1.] [1. 1. 1.]] [[7 7] [7 7]] [0 2 4 6 8] [0. 0.25 0.5 0.75 1. ]

Two details that catch people. np.zeros and np.ones give floats, not integers, which is usually what you want and occasionally a surprise. And the last two look similar but ask different questions: arange(0, 10, 2) is "from 0, in steps of 2, stopping before 10", while linspace(0, 1, 5) is "five values from 0 to 1, including 1, evenly spaced". When you know the step, use arange; when you know how many you want, use linspace.

تفصيلان يُوقعان الناس. فـ np.zeros وnp.ones تعطيان أعدادًا عشرية لا صحيحة، وهو ما تريده عادةً ومفاجأةٌ أحيانًا. والأخيرتان تتشابهان لكنهما تسألان سؤالين مختلفين: فـ arange(0, 10, 2) تعني «من 0 بخطوة 2 ونتوقف قبل 10»، بينما linspace(0, 1, 5) تعني «خمس قيم من 0 إلى 1 شاملةً 1 بتباعد منتظم». فإذا عرفت الخطوة فاستعمل arange، وإذا عرفت العدد المطلوب فاستعمل linspace.

Exercise 10.2 — Percentages without a loopتمرين 10.2 — نسب مئوية بلا حلقة

Each paper is out of 120. Turn the raw marks into percentages, rounded to one decimal place, in a single expression with no for.

كل ورقة من 120. حوّل العلامات الخام نسبًا مئوية، مقرَّبة إلى منزلة عشرية واحدة، في تعبير واحد بلا for.

raw = np.array([48, 66, 84, 102, 120])
# one line here
# expected: [40.  55.  70.  85. 100.]
Show solutionإظهار الحل 
percent = np.round(raw / 120 * 100, 1)
print(percent, percent.dtype)
[ 40. 55. 70. 85. 100.] float64

Note the dtype: raw was int64 and the result is float64, because dividing always produces decimals even when they happen to come out whole. If you had written raw //= 120 to keep it integer, every percentage would have become 0.

لاحظ dtype: فـ raw كانت int64 والنتيجة float64، لأن القسمة تنتج عشريات دائمًا حتى حين تخرج صحيحة اتفاقًا. ولو كتبت raw //= 120 لإبقائها صحيحة لصارت كل نسبة 0.

Exercise 10.3 — Build the table three waysتمرين 10.3 — ابنِ الجدول بثلاث طرق

Produce a 4×3 array of zeros as a float64, a 4×3 array of zeros as an int64, and a 1-D array holding 0.0, 0.5, 1.0, 1.5, 2.0. Print the shape and dtype of each.

أنتج مصفوفة أصفار 4×3 من نوع float64، ومصفوفة أصفار 4×3 من نوع int64، ومصفوفة أحادية تحمل 0.0 و0.5 و1.0 و1.5 و2.0. واطبع shape وdtype لكلٍّ.

Show solutionإظهار الحل 
a = np.zeros((4, 3))
b = np.zeros((4, 3), dtype=int)
c = np.linspace(0, 2, 5)

for arr in (a, b, c):
    print(arr.shape, arr.dtype)
(4, 3) float64 (4, 3) int64 (5,) float64

Two things to take from this. The shape goes in as a tuple — np.zeros(4, 3) is an error, because the second argument is the dtype. And np.arange(0, 2.5, 0.5) would also work for c, but linspace is safer with decimal steps: a step that cannot be stored exactly can leave arange one value short or one value long.

خذ من هذا أمرين. فالشكل يدخل صفًّا (tuple) — فـ np.zeros(4, 3) خطأ، لأن الوسيط الثاني هو النوع. وnp.arange(0, 2.5, 0.5) تنجح لـ c أيضًا، لكن linspace أسلم مع الخطوات العشرية: فخطوةٌ لا يمكن تخزينها تمامًا قد تترك arange ناقصةً قيمةً أو زائدةً قيمة.

What does np.array([1, 2, 3]) * 3 give, and why is it different from [1, 2, 3] * 3?ماذا تعطي np.array([1, 2, 3]) * 3، ولماذا تختلف عن [1, 2, 3] * 3؟

The same symbol means two different things depending on what is to its left, and both are defined, so neither errors. That is what makes the list version dangerous: marks * 2 on a class of thirty produces a class of sixty, every student twice, and the average is unchanged — so a summary report looks completely normal.
الرمز نفسه يعني شيئين مختلفين بحسب ما على يساره، وكلاهما معرَّف، فلا تُخطئ أيٌّ منهما. وذلك ما يجعل نسخة القائمة خطيرة: فـ marks * 2 على صفّ ثلاثين تُنتج صفَّ ستين، كلُّ طالب مرتين، والمتوسط لم يتغير — فيبدو التقرير الملخَّص طبيعيًا تمامًا.

An array is built from [1, 2, 3] and then a[0] = 9.7 is assigned. What does the array hold?تُبنى مصفوفة من [1, 2, 3] ثم يُسنَد a[0] = 9.7. فماذا تحمل المصفوفة؟

An array's dtype is fixed when it is built and assignment never changes it — the value is converted to fit, not the other way round. Note it truncates rather than rounding, so 9.7 becomes 9 and not 10; the fourth answer is the one most people pick. The whole category of bug is prevented by one argument at build time: dtype=float.
نوعُ المصفوفة يُثبَّت عند بنائها ولا يغيّره الإسناد أبدًا — فالقيمة تُحوَّل لتناسب، لا العكس. ولاحظ أنها تبتر ولا تقرّب، فتصير 9.7 هي 9 لا 10؛ والجواب الرابع هو ما يختاره أكثر الناس. وفصيلةُ الخلل كلها تُمنع بوسيط واحد عند البناء: dtype=float.

Key takeawaysالخلاصة

What to carry into the next lessonما تحمله إلى الدرس التالي

  • A list is a container; an array is a vector of numbers. + and * mean join and repeat on one, and arithmetic on every element on the other.القائمة حاوية؛ والمصفوفة متجهُ أعداد. فـ + و* تعنيان الإلحاق والتكرار في الأولى، والحساب على كل عنصر في الثانية.
  • One operation replaces a whole loop, and a comparison gives an array of True/False — which Lesson 13 turns into a way of selecting rows.عمليةٌ واحدة تحلّ محلّ حلقة كاملة، والمقارنة تعطي مصفوفة True/False — ويحوّلها الدرس 13 طريقةً لاختيار الصفوف.
  • Every array has exactly one dtype, chosen at build time from what you gave it: all whole numbers gives int64, one decimal promotes everything to float64, one string turns it all into text.لكل مصفوفة dtype واحد بالضبط، يُختار عند البناء مما أعطيتها: فالصحيحة كلها تعطي int64، وعشريٌّ واحد يرفع الجميع إلى float64، ونصٌّ واحد يحوّل الكل كتابةً.
