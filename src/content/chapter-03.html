Concept 1 — An array does arithmetic; a list does notالمفهوم 1 — المصفوفة تحسب؛ والقائمة لا

The problemالمشكلة

The ministry adds five marks to every paper. You have the marks in a list, and the obvious thing to write does not do the obvious thing.

تضيف الوزارة خمس علامات إلى كل ورقة. والعلامات عندك في قائمة، والشيءُ البديهي الذي تكتبه لا يفعل الشيء البديهي.

The starting codeالكود الابتدائي

marks = [40, 55, 70, 85, 100]

print(marks + 5)
TypeError: can only concatenate list (not "int") to list

Fair enough — + on a list means "join another list on the end", so adding a number is meaningless. Try doubling instead, where * is defined:

لا بأس — فـ + على قائمة تعني «ألحِق قائمة أخرى في النهاية»، فإضافةُ عدد بلا معنى. جرّب المضاعفة بدلًا من ذلك، حيث * معرَّفة:

print(marks * 2)
[40, 55, 70, 85, 100, 40, 55, 70, 85, 100]

Diagnosisالتشخيص

This one is worse than the error, because it worked. marks * 2 did not double thirty marks; it produced sixty marks. A class of thirty is now a class of sixty, every student appears twice, and the average is unchanged so the mistake is invisible in a summary. The first version at least refused.

هذه أسوأ من الخطأ، لأنها نجحت. فـ marks * 2 لم تضاعف ثلاثين علامة؛ بل أنتجت ستين علامة. فصارَ صفُّ الثلاثين صفَّ ستين، وظهر كل طالب مرتين، والمتوسط لم يتغير فصار الخطأ غير مرئي في أي ملخّص. والنسخة الأولى رفضت على الأقل.

Name the defectسمِّ العيب

A list is a container, so its operators are container operations: join and repeat. You wanted arithmetic on every element, and a list has no idea that is what its contents are for. The usual answer is a loop:

القائمة حاوية، فعملياتها عمليات حاويات: الإلحاق والتكرار. وأنت أردت حسابًا على كل عنصر، والقائمةُ لا تدري أن ذلك ما محتواها له. والجواب المعتاد حلقة:

adjusted = []
for m in marks:
    adjusted.append(m + 5)
print(adjusted)
[45, 60, 75, 90, 105]

Correct, and four lines. Now do it for three subjects, then scale them, then centre them, and the file fills up with loops that all say the same thing in slightly different words.

صحيح، وأربعة أسطر. والآن افعلها لثلاث مواد، ثم قِسها، ثم مركِزها، فيمتلئ الملف بحلقات تقول الشيء نفسه بكلمات مختلفة قليلًا.

Conversion — a container that knows it holds numbersالتحويل — حاوية تعلم أنها تحمل أعدادًا

import numpy as np

marks = np.array([40, 55, 70, 85, 100])

print(marks + 5)
print(marks * 2)
print(marks / 100)
print(marks > 60)
[ 45 60 75 90 105] [ 80 110 140 170 200] [0.4 0.55 0.7 0.85 1. ] [False False True True True]

Every operator now means "do this to each element and give me an array of the answers". The loop is gone, and so is the chance of writing it wrongly. The last line is worth a second look: comparing an array to a number gives an array of True and False, one per mark, which is the basis of everything in Lesson 13.

صار كل معامل يعني «افعل هذا بكل عنصر وأعطني مصفوفة الأجوبة». فاختفت الحلقة، واختفت معها فرصةُ كتابتها خطأً. والسطر الأخير يستحق نظرة ثانية: فمقارنة مصفوفة بعدد تعطي مصفوفة True وFalse، واحدةً لكل علامة، وهي أساس كل ما في الدرس 13.

Why this is also much fasterولماذا هذا أسرع كثيرًا أيضًا

A Python loop over a million marks executes a million separate Python steps. marks + 5 hands the whole array to compiled code that walks the memory once. The speed is the famous part, but it is the second reason to use an array; the first is that one line cannot be written wrongly in six different places.

حلقةُ بايثون على مليون علامة تنفّذ مليون خطوة بايثون منفصلة. أما marks + 5 فتسلّم المصفوفة كلها إلى كود مترجَم يمشي في الذاكرة مرة واحدة. والسرعة هي الجزء الشهير، لكنها السبب الثاني لاستعمال المصفوفة؛ والأول أن سطرًا واحدًا لا يمكن كتابته خطأً في ستة مواضع مختلفة.

What does this print?
a = np.array([1, 2, 3])
a[0] = 2.9
print(a)ماذا يطبع هذا؟
a = np.array([1, 2, 3])
a[0] = 2.9
print(a)

Cut, not rounded: the decimal part is thrown away, so 2.9 becomes 2 and 2.99 would too. And the array does not change its mind about its type — it was decided when the array was built, which is why the second option is wrong in a more interesting way than the first. If the marks might have decimals, say so at build time: np.array([1, 2, 3], dtype=float).
قطعٌ لا تقريب: فالجزء العشري يُرمى، فتصير 2.9 اثنين، وكذلك 2.99. ولا تغيّر المصفوفة رأيها في نوعها — فقد قُرِّر عند بنائها، ولذلك كان الخيار الثاني خاطئًا بوجه أطرف من الأول. فإن كانت العلامات قد تحمل عشريات فقل ذلك عند البناء: np.array([1, 2, 3], dtype=float).

Concept 2 — What an array gave up: one type for everythingالمفهوم 2 — ما تخلّت عنه المصفوفة: نوعٌ واحد للجميع

The arithmetic is not free. A list can hold a number, a string and another list at once; an array decides on one type when it is built and applies it to every value, for ever.

الحساب ليس مجانًا. فالقائمة تحمل عددًا ونصًّا وقائمة أخرى معًا؛ والمصفوفة تقرّر نوعًا واحدًا عند بنائها وتطبّقه على كل قيمة إلى الأبد.

whole = np.array([40, 55, 70])
print(whole, whole.dtype)

decimal = np.array([40, 55, 70.5])
print(decimal, decimal.dtype)

mixed = np.array([1, "two", 3])
print(mixed, mixed.dtype)
[40 55 70] int64 [40. 55. 70.5] float64 ['1' 'two' '3'] <U21

Three different decisions, none of them announced. All whole numbers gives int64. One decimal among them promotes every value to float64 — notice 40. with a trailing dot. And one string turns the numbers into text: <U21 means "unicode string, up to 21 characters", and mixed * 2 would now repeat the text rather than double anything.

ثلاثة قرارات مختلفة، لم يُعلَن أيٌّ منها. فالأعداد الصحيحة كلها تعطي int64. وعشريٌّ واحد بينها يرفع كل قيمة إلى float64 — لاحظ 40. بالنقطة اللاحقة. ونصٌّ واحد يحوّل الأعداد كتابةً: فـ <U21 تعني «نص يونيكود حتى 21 محرفًا»، وستكرّر mixed * 2 النصَّ الآن بدل مضاعفة أي شيء.

The trap: an integer array silently truncatesالفخ: مصفوفة الأعداد الصحيحة تبتر بصمت

marks = np.array([40, 55, 70])
print(marks.dtype)

marks[0] = 2.9
print(marks)
int64 [ 2 55 70]

2.9 went in and 2 came out. The array is int64, it has nowhere to put a fraction, and it does not consider that worth mentioning. Scale an integer array by 0.9 and assign the result back into it and every mark loses its decimal part, quietly, for every student. The fix is to decide the type when you build it:

دخلت 2.9 وخرجت 2. فالمصفوفة int64، ولا موضع فيها لكسر، ولا ترى ذلك جديرًا بالذكر. وقِس مصفوفةَ أعداد صحيحة بـ 0.9 وأسند النتيجة إليها يفقد كلُّ علامة جزأها العشري، بصمت، لكل طالب. والإصلاح أن تقرّر النوع عند البناء:

marks = np.array([40, 55, 70], dtype=float)
marks[0] = 2.9
print(marks, marks.dtype)
[ 2.9 55. 70. ] float64

Shape: the same numbers, arrangedالشكل: الأعداد نفسها، مرتّبةً

The class sat three subjects, so the natural arrangement is a table: one row per student, one column per subject.

امتحن الصفُّ في ثلاث مواد، فالترتيب الطبيعي جدول: صفٌّ لكل طالب وعمودٌ لكل مادة.

                  [60, 65, 90],

print(marks.ndim)

Arithmetic works on the table exactly as it did on the row, element by element, with no loops and no nesting:

والحساب يعمل على الجدول تمامًا كما عمل على الصفّ، عنصرًا عنصرًا، بلا حلقات ولا تعشيش:

[[ 45 60 75] [ 65 70 95] [ 85 80 55]] (3, 3) (3, 3)

Making arrays without typing every numberصنع المصفوفات دون كتابة كل عدد

print(np.zeros(3))
print(np.ones((2, 3)))
print(np.full((2, 2), 7))
print(np.arange(0, 10, 2))
print(np.linspace(0, 1, 5))
[0. 0. 0.] [[1. 1. 1.] [1. 1. 1.]] [[7 7] [7 7]] [0 2 4 6 8] [0. 0.25 0.5 0.75 1. ]

Two details that catch people. np.zeros and np.ones give floats, not integers, which is usually what you want and occasionally a surprise. And the last two look similar but ask different questions: arange(0, 10, 2) is "from 0, in steps of 2, stopping before 10", while linspace(0, 1, 5) is "five values from 0 to 1, including 1, evenly spaced". When you know the step, use arange; when you know how many you want, use linspace.

تفصيلان يُوقعان الناس. فـ np.zeros وnp.ones تعطيان أعدادًا عشرية لا صحيحة، وهو ما تريده عادةً ومفاجأةٌ أحيانًا. والأخيرتان تتشابهان لكنهما تسألان سؤالين مختلفين: فـ arange(0, 10, 2) تعني «من 0 بخطوة 2 ونتوقف قبل 10»، بينما linspace(0, 1, 5) تعني «خمس قيم من 0 إلى 1 شاملةً 1 بتباعد منتظم». فإذا عرفت الخطوة فاستعمل arange، وإذا عرفت العدد المطلوب فاستعمل linspace.

An array's dtype is fixed when it is built and assignment never changes it — the value is converted to fit, not the other way round. Concept 1 — A slice of an array is a window, not a photographالمفهوم 1 — قطعة المصفوفة نافذة لا صورة

The problemالمشكلة

Three students sat a resit. You take their marks out of the class array, cap them at 60 as the regulations require, and report both the resit marks and the original class. One of those two is now wrong.

أعاد ثلاثة طلبة الامتحان. فتأخذ علاماتهم من مصفوفة الصفّ، وتحصرها عند 60 كما تقتضي اللائحة، وتبلّغ علاماتِ الإعادة والصفَّ الأصلي. وأحد هذين خطأٌ الآن.

The starting codeالكود الابتدائي

import numpy as np

marks = np.array([40, 55, 70, 85, 100])

resit = marks[1:4]
resit[0] = 60

print("resit:", resit)
print("class:", marks)
resit: [60 70 85] class: [ 40 60 70 85 100]

The class array changed. Nobody assigned to marks; the only assignment in the program is to resit. Do exactly the same thing with a list and it behaves the way you expected:

تغيّرت مصفوفة الصفّ. ولم يُسنِد أحدٌ إلى marks؛ فالإسناد الوحيد في البرنامج إلى resit. وافعل الشيء نفسه بقائمة تتصرف كما توقعت:

marks = [40, 55, 70, 85, 100]
resit = marks[1:4]
resit[0] = 60

print("resit:", resit)
print("class:", marks)
resit: [60, 70, 85] class: [40, 55, 70, 85, 100]

Diagnosisالتشخيص

Slicing a list copies the chosen items into a new list. Slicing an array does not copy anything: it hands back a second array object that points at the same memory, starting a little further along. The two names are two windows onto one block of numbers, so writing through either is visible through both.

تقطيعُ القائمة ينسخ العناصر المختارة إلى قائمة جديدة. وتقطيعُ المصفوفة لا ينسخ شيئًا: بل يُعيد كائن مصفوفة ثانيًا يشير إلى الذاكرة نفسها، بادئًا أبعد قليلًا. فالاسمان نافذتان على كتلة أعداد واحدة، فالكتابةُ عبر أيٍّ منهما تُرى عبر كليهما.

Why NumPy does this on purposeلماذا تفعل نمباي هذا متعمدةً

A million-row table sliced into a hundred overlapping windows would be a hundred million numbers copied, for nothing, if all you wanted was to read them. Not copying is what makes a slice instant regardless of size. The cost is that you have to know when you are holding a window, and the single word .copy() is how you stop.

جدولٌ بمليون صفّ مقطَّعٌ إلى مئة نافذة متداخلة سيكون مئة مليون عدد منسوخة بلا طائل، إن كان كل مرادك قراءتها. وعدمُ النسخ هو ما يجعل القطعة فورية أيًّا كان الحجم. والثمنُ أن عليك أن تعرف متى تمسك بنافذة، وكلمةُ .copy() الواحدة هي كيف تتوقف.

marks = np.array([40, 55, 70, 85, 100])

resit = marks[1:4].copy()
resit[0] = 60

print("resit:", resit)
print("class:", marks)
print("is it a window?", marks[1:4].base is not None, resit.base is None)
resit: [60 70 85] class: [ 40 55 70 85 100] is it a window? True True

.base is how you ask. A view's base is the array it looks into; an independent array's base is None. You will not write that line often, but it is the fastest way to settle an argument with yourself at two in the morning.

.base هي كيف تسأل. فـbase النافذة هي المصفوفة التي تطلّ عليها؛ وbase المصفوفة المستقلة هي None. ولن تكتب ذلك السطر كثيرًا، لكنه أسرع طريقة لحسم خصومة مع نفسك في الثانية صباحًا.

What does print(a) show?
a = np.array([10, 20, 30, 40, 50])
b = a[::2]
b[0] = 0ماذا يُظهر print(a)؟

b = a[::2]
b[0] = 0

The second option is the tempting one, and the reason it is wrong is worth holding on to: the step is exactly what makes the window describable. “Every other element” is a start, a step and a stop, so nothing needs to move. Compare a[[0, 2, 4]], which selects the same three elements and is a copy, because a list of positions carries no rule NumPy can follow.
الخيار الثاني هو المُغري، وسببُ خطئه جديرٌ بالحفظ: فالخطوةُ هي بالضبط ما يجعل النافذة قابلةً للوصف. فـ«كل عنصر ثانٍ» بدايةٌ وخطوةٌ ونهاية، فلا شيء يحتاج أن يتحرّك. وقارن a[[0, 2, 4]] التي تختار العناصر الثلاثة نفسها وهي نسخة، لأن قائمة المواضع لا تحمل قاعدةً تتبعها نمباي.

The middle subject was marked too harshly and every mark in it is to go up by 5. Keep an untouched archive of the original table, apply the change in place to the real table, and print the middle subject from each to prove both survived.

صُحِّحت المادة الوسطى بقسوة فكل علامة فيها ستزيد 5. احفظ أرشيفًا سليمًا للجدول الأصلي، وطبّق التغيير في مكانه على الجدول الحقيقي، واطبع المادة الوسطى من كلٍّ لتُثبت أن الاثنين نجَوا.

marks = np.array([[40., 55., 70.],
                  [60., 65., 90.],
                  [80., 75., 50.]])
# archive, then moderate
# expected: [55. 65. 75.] then [60. 70. 80.]
Show solutionإظهار الحل

print(marks[:, 1])
[55. 65. 75.] [60. 70. 80.]

Two uses of the same rule, in opposite directions. archive = marks.copy() must copy, because a view would change along with the table and archive nothing. marks[:, 1] += 5 must not copy, because the point is to change the real table — writing through a column view is how you moderate one subject in place.

استعمالان للقاعدة نفسها في اتجاهين متعاكسين. فـ archive = marks.copy() يجب أن تنسخ، لأن النافذة ستتغير مع الجدول فلا تؤرشف شيئًا. وmarks[:, 1] += 5 يجب ألّا تنسخ، لأن المقصود تغييرُ الجدول الحقيقي — فالكتابةُ عبر نافذة عمود هي كيف تعدّل مادةً واحدة في مكانها.

جرّبه بـ archive = marks بدلًا من ذلك واطبع مرة أخرى: فيُظهر السطران العلامات المعدَّلة، لأن الاسمين مصفوفةٌ واحدة. وذلك ليس نافذةً حتى — بل كائنٌ واحد بلافتتين.

Concept 2 — Reaching into a tableالمفهوم 2 — المدّ داخل الجدول

The class table is one row per student and one column per subject. Indexing it takes one number per dimension, separated by a comma, and that comma is the whole difference from a list of lists.

جدولُ الصفّ صفٌّ لكل طالب وعمودٌ لكل مادة. وفهرستُه تأخذ عددًا لكل بُعد، مفصولًا بفاصلة، وتلك الفاصلة هي كل الفرق عن قائمة القوائم.

marks = np.array([[40, 55, 70],
                  [60, 65, 90],
                  [80, 75, 50]])

print(marks[1, 2])
print(marks[0])
print(marks[:, 1])
print(marks[1:, 1:])

  • marks[0] — a whole row, which is one student across all subjects.marks[0] — صفٌّ كامل، وهو طالب واحد في كل المواد.
  • marks[:, 1] — the colon means "every row", so this is a whole column: one subject across all students. This is the form people forget, and it is the one you need most.marks[:, 1] — النقطتان تعنيان «كل الصفوف»، فهذا عمودٌ كامل: مادةٌ واحدة لكل الطلبة. وهذه الصيغة ينساها الناس، وهي أكثر ما تحتاج.

Every one of those is a view. Writing into a column changes the table:

وكلُّ واحدة من تلك نافذة. فالكتابة في عمود تغيّر الجدول:

Which is sometimes exactly what you want — moderating one subject in place is a real task and this is the neat way to do it. The danger is doing it by accident, having thought you were working on a copy.

وهذا أحيانًا بالضبط ما تريد — فتعديل مادة واحدة في مكانها مهمةٌ حقيقية وهذه الطريقة الأنيقة لها. والخطر أن تفعله بالصدفة وأنت تحسب أنك تعمل على نسخة.

Which kinds of indexing copy?أي أنواع الفهرسة تنسخ؟

This is the part worth memorising, because it is not obvious and it decides whether your edit escapes.

هذا هو الجزء الجدير بالحفظ، لأنه ليس بديهيًا وهو يقرّر هل يفلت تعديلك.

Written asيُكتب هكذا Givesيعطي
a[1:4], a[:, 0], a[1:, 1:] A view. Writing to it writes to the original.نافذة. فالكتابة فيها تكتب في الأصل.
a[[0, 2, 4]] (a list of positions)(قائمة مواضع) A copy. The positions are not evenly spaced, so there is no window to describe.نسخة. فالمواضع غير متباعدة بانتظام، فلا نافذة توصَف.

The rule behind the table is mechanical, not arbitrary. A view has to be describable as "start here, take every nth number, stop there" — that is all the extra information an array object carries. Positions 0, 2 and 4 happen to fit that, but [0, 2, 3] would not, and NumPy will not decide case by case, so the whole family copies.

والقاعدةُ وراء الجدول آليةٌ لا اعتباطية. فالنافذة يجب أن تُوصَف بـ«ابدأ هنا، وخذ كل عدد ن، وتوقف هناك» — وذلك كل ما يحمله كائن المصفوفة من معلومات إضافية. والمواضع 0 و2 و4 تنطبق عليها اتفاقًا، لكن [0, 2, 3] لا تنطبق، ولن تقرّر نمباي حالةً حالةً، فتنسخ الفصيلة كلها.

A warning you will meetتحذيرٌ ستقابله

Writing into a mask, as opposed to writing into the copy a mask returned, does change the original and is the normal way to cap values:

الكتابةُ في القناع، خلافًا للكتابة في النسخة التي أعادها القناع، تغيّر الأصل وهي الطريقة المعتادة لحصر القيم:

print(marks)
[40 55 70 80 80]

The difference is that here the mask is on the left of the =, so NumPy is being told where to write rather than being asked for a selection. Compare it with high = marks[marks > 80] above, which asks for a selection and gets a copy.

والفرق أن القناع هنا على يسار علامة =، فتُخبَر نمباي أين تكتب لا تُسأل عن اختيار. قارنه بـ high = marks[marks > 80] أعلاه، فهي تطلب اختيارًا وتنال نسخة.

Exercise 11.2 — Moderate one subject without touching the othersتمرين 11.2 — عدّل مادة واحدة دون مسّ الأخريات

Raise every mark in the third subject by 10, capped at 100, leaving the other two columns alone. Then print the table to prove the other columns did not move.

ارفع كل علامة في المادة الثالثة بمقدار 10، محصورةً عند 100، وادع العمودين الآخرين. ثم اطبع الجدول لتثبت أن العمودين الآخرين لم يتحركا.

marks = np.array([[40, 55, 70],
                  [60, 65, 90],
                  [80, 75, 50]])

# [[ 40  55  80]
#  [ 60  65 100]

Shapes That Stretch: Broadcastingأشكالٌ تتمدّد: البثّ

By the end of this lesson you will subtract three subject averages from a table of nine marks and watch it work, subtract three student averages from the same table and watch it work just as smoothly while producing nonsense, and learn the one rule that tells the two apart before you run anything.

بنهاية هذا الدرس ستطرح ثلاثة متوسطات مواد من جدول فيه تسع علامات وتراه ينجح، ثم تطرح ثلاثة متوسطات طلبة من الجدول نفسه وتراه ينجح بالسلاسة نفسها وهو يُنتج هراءً، وتتعلّم القاعدة الواحدة التي تميّز بينهما قبل أن تشغّل شيئًا.

Before you startقبل أن تبدأ

Finish Lesson 10 and Lesson 11. This lesson is entirely about shape, so if (3, 3) and (3,) do not yet read as different things, re-read the shape section first. No mathematics beyond subtraction is used.

أنجز الدرس 10 والدرس 11. فهذا الدرس عن shape كلّه، فإن لم تكن (3, 3) و(3,) تُقرآن شيئين مختلفين بعد فأعد قراءة قسم الشكل أولًا. ولا تُستعمل رياضيات غير الطرح.

Concept 1 — A smaller shape is stretched to fit a larger oneالمفهوم 1 — الشكل الأصغر يُمدَّد ليناسب الأكبر

The problemالمشكلة

Three subjects were marked by three different examiners and one marked harder than the others. To compare students fairly you want every mark expressed as a distance from its own subject's average. Written as a loop that is two nested fors and an index you will get wrong at least once.

صحّح ثلاثَ المواد ثلاثةُ ممتحنين وصحّح أحدهم أقسى من الآخرين. ولمقارنة الطلبة بإنصاف تريد كل علامة معبَّرًا عنها بُعدًا عن متوسط مادتها. ومكتوبًا حلقةً فهو حلقتا for متداخلتان وفهرسٌ ستخطئه مرة على الأقل.

import numpy as np

marks = np.array([[40., 55., 70.],
                  [60., 65., 90.],
                  [80., 75., 50.]])

subject_mean = marks.mean(axis=0)
print(subject_mean, subject_mean.shape)

print(marks - subject_mean)
[60. 65. 70.] (3,) [[-20. -10. 0.] [ 0. 0. 20.] [ 20. 10. -20.]]

Three numbers were subtracted from nine, and nobody complained. The first column had 60 taken off it, the second 65, the third 70 — each column got its own subject's average, which is exactly what was wanted. That is broadcasting: when two shapes are not the same, NumPy stretches the smaller one rather than refusing.

طُرحت ثلاثة أعداد من تسعة، ولم يعترض أحد. فالعمود الأول طُرح منه 60، والثاني 65، والثالث 70 — فنال كل عمود متوسط مادته، وهو المراد بالضبط. وذلك هو البثّ: فحين لا يتطابق الشكلان تمدّد نمباي الأصغر بدل أن ترفض.

The rule, in one lineالقاعدة في سطر

Compare the shapes from the right. A dimension fits if it is equal, or 1, or absent.قارن الشكلين من اليمين. ويناسب البُعد إن كان متساويًا أو 1 أو غائبًا.

Write the two shapes one above the other, right-aligned, and check each column. Equal is fine. A 1 is fine and gets repeated. Missing is fine and is treated as 1. Anything else is an error.

اكتب الشكلين أحدهما فوق الآخر محاذَيين إلى اليمين، وافحص كل عمود. فالتساوي مقبول. و1 مقبولة وتُكرَّر. والغياب مقبول ويُعامَل 1. وما عدا ذلك خطأ.

print(marks - np.array([1., 2.]))
ValueError: operands could not be broadcast together with shapes (3,3) (2,)

Read that message as a gift. It prints both shapes, in the order you wrote them, so you rarely need to work out what went wrong — you need to work out which of the two is not what you meant.

اقرأ تلك الرسالة هديةً. فهي تطبع الشكلين بالترتيب الذي كتبتهما به، فنادرًا ما تحتاج إلى استنتاج ما الخطأ — بل تحتاج إلى استنتاج أيُّهما ليس ما قصدت.

The three shapes you will actually useالأشكال الثلاثة التي ستستعملها فعلًا

a = np.array([[1, 2, 3],
              [4, 5, 6]])

print(a + 10)
print(a + np.array([10, 20, 30]))
print(a + np.array([[100],
                    [200]]))
[[11 12 13] [14 15 16]] [[11 22 33] [14 25 36]] [[101 102 103] [204 205 206]]

A single number stretches in every direction. A row of shape (3,) is reused down the rows, so each column gets its own number. A column of shape (2, 1) is reused across the columns, so each row gets its own number. Those three cover nearly everything you will write, and the only one that needs care is telling the second apart from the third.

العددُ المفرد يتمدّد في كل اتجاه. والصفُّ ذو الشكل (3,) يُعاد استعماله نزولًا على الصفوف، فينال كل عمود عددَه. والعمودُ ذو الشكل (2, 1) يُعاد استعماله عرضًا على الأعمدة، فينال كل صفّ عددَه. وتلك الثلاثة تغطي كل ما ستكتبه تقريبًا، والوحيد الذي يحتاج حذرًا هو تمييز الثانية عن الثالثة.

A table t has shape (2, 3). What does t + np.array([1., 2.]) do?جدولٌ t شكله (2, 3). فماذا تفعل t + np.array([1., 2.])؟

The second option is what you probably meant, and it is the whole lesson: two numbers for two rows have to be written as a column, [:, None], shape (2, 1). Flat arrays always line up with the columns. The fourth option is worth refuting explicitly — broadcasting never repeats a dimension of size 2 to fill a dimension of size 3; only a dimension of exactly 1 is stretched.
الخيار الثاني هو ما قصدتَه على الأرجح، وهو الدرس كله: فعددان لصفّين يجب أن يُكتبا عمودًا [:, None] بالشكل (2, 1). فالمصفوفاتُ المسطّحة تُحاذي الأعمدة دائمًا. والخيار الرابع جديرٌ بالدحض صريحًا — فالبثُّ لا يكرّر أبدًا بُعدًا حجمه 2 ليملأ بُعدًا حجمه 3؛ ولا يُمدَّد إلا بُعدٌ حجمه 1 بالضبط.

Concept 2 — The shape that fits when it should notالمفهوم 2 — الشكل الذي ينطبق حين لا ينبغي

The problemالمشكلة

Now do the other comparison. Instead of asking how each mark compares with its subject, ask how it compares with that student's own average — who is strong at maths relative to themselves. Change one number and run it.

والآن افعل المقارنة الأخرى. فبدل السؤال كيف تقارَن كل علامة بمادتها، اسأل كيف تقارَن بمتوسط ذلك الطالب نفسه — من هو قويٌّ في الرياضيات نسبةً إلى نفسه. غيّر عددًا واحدًا وشغّله.

student_mean = marks.mean(axis=1)
print(student_mean, student_mean.shape)

print(marks - student_mean)
[55. 71.66666667 68.33333333] (3,) [[-15. -16.66666667 1.66666667] [ 5. -6.66666667 21.66666667] [ 25. 3.33333333 -18.33333333]]

Diagnosisالتشخيص

Nine numbers came out, no error was raised, and every one of them is wrong. The row of student averages has shape (3,), exactly like the row of subject averages did, so the rule applied it the only way it knows: across each row. Student 1's average was subtracted from the first column — from student 1's maths, student 2's maths and student 3's maths — and student 2's average from the second column, and so on. Each number is a real subtraction between two unrelated quantities.

خرجت تسعة أعداد ولم يُرفع أي خطأ وكلُّها خطأ. فصفُّ متوسطات الطلبة شكله (3,)، تمامًا كصفّ متوسطات المواد، فطبّقته القاعدة بالطريقة الوحيدة التي تعرفها: عرضًا على كل صفّ. فطُرح متوسط الطالب 1 من العمود الأول — من رياضيات الطالب 1 ورياضيات الطالب 2 ورياضيات الطالب 3 — وطُرح متوسط الطالب 2 من العمود الثاني وهكذا. فكل عدد طرحٌ حقيقي بين كمّيتين لا علاقة بينهما.

Name the defectسمِّ العيب

A shape of (3,) does not say whether its three numbers are per column or per row. The table is square, so both readings fit the rule, and NumPy always picks the same one. Broadcasting cannot know what you meant; it only knows what shape you handed it.

الشكلُ (3,) لا يقول هل أعداده الثلاثة لكل عمود أم لكل صفّ. والجدول مربّع، فالقراءتان تنطبقان على القاعدة، وتختار نمباي الواحدةَ نفسها دائمًا. فالبثُّ لا يمكنه معرفة ما قصدت؛ إنما يعرف أي شكل سلّمته.

The fix: say which direction you meantالإصلاح: قل أي اتجاه قصدت

Turn the row of three into a column of three, so its shape says "one number per row" out loud.

حوّل صفَّ الثلاثة عمودًا من ثلاثة، فيقول شكله «عددٌ لكل صفّ» بصوت مسموع.

print(student_mean.shape)
print(student_mean[:, None].shape)

print(marks - student_mean[:, None])
(3,) (3, 1) [[-15. 0. 15. ] [-11.66666667 -6.66666667 18.33333333] [ 11.66666667 6.66666667 -18.33333333]]

[:, None] means "keep every element, and add a new dimension of length 1 at the end". (3,) becomes (3, 1), which right-aligned against (3, 3) matches 3 with 3 and stretches the 1 — across the columns, which is what you wanted. Check the first row of the result: −15, 0, +15 for marks of 40, 55 and 70 around an average of 55. That is a student compared with themselves.

[:, None] تعني «أبقِ كل عنصر، وأضف بُعدًا جديدًا طوله 1 في النهاية». فتصير (3,) هي (3, 1)، ومحاذاةً إلى اليمين أمام (3, 3) تطابق 3 مع 3 وتمدّد الـ1 — عرضًا على الأعمدة، وهو ما أردت. وافحص الصفّ الأول من النتيجة: −15 و0 و+15 لعلامات 40 و55 و70 حول متوسط 55. وذلك طالبٌ مقارَنٌ بنفسه.

Three ways to write the same thingثلاث طرق لكتابة الشيء نفسه

student_mean[:, None], student_mean.reshape(-1, 1) and marks.mean(axis=1, keepdims=True) all give shape (3, 1). The last is the best of the three, because it never lets the wrong shape exist in the first place — the dimension is kept at the moment it would have been dropped, rather than put back afterwards. Lesson 13 uses it properly.

student_mean[:, None] وstudent_mean.reshape(-1, 1) وmarks.mean(axis=1, keepdims=True) تعطي كلها الشكل (3, 1). وآخرها أفضلها، لأنه لا يدع الشكل الخطأ يوجد أصلًا — فيُحفَظ البُعد في اللحظة التي كان سيسقط فيها، بدل إعادته بعدها. ويستعمله الدرس 13 كما ينبغي.

Exercise 12.2 — Scale each subject to 0–1تمرين 12.2 — قِس كل مادة إلى 0–1

Put every mark on a 0-to-1 scale within its own subject, so the weakest mark in each column becomes 0 and the strongest becomes 1. Two lines, no loop. This is the MinMaxScaler of Lesson 8, done to a whole table at once.

ضع كل علامة على مقياس من 0 إلى 1 داخل مادتها، فتصير أضعف علامة في كل عمود 0 وأقواها 1. سطران بلا حلقة. وهذا هو MinMaxScaler من الدرس 8، مطبَّقًا على جدول كامل دفعةً.

marks = np.array([[40., 55., 70.],
                  [60., 65., 90.],
                  [80., 75., 50.]])

# [[0.  0.  0.5]
#  [0.5 0.5 1. ]
#  [1.  1.  0. ]]

Both low and high have shape (3,) and both broadcast down the rows, so each column is scaled by its own two numbers. Shapes are compared from the right, so 5 is never compared with 3 — the 5 has nothing opposite it and is simply kept. The third answer is the one to understand rather than just reject: that is what you would get from shape (5, 1), and it is the whole subject of Concept 2. With a 5×3 table the two readings have different shapes and a mistake raises an error; with a square table they do not, and it does not.
تُقارَن الأشكال من اليمين، فلا تُقارَن 5 بـ3 أبدًا — فالـ5 لا شيء يقابلها وتُحفَظ ببساطة. والجواب الثالث يُفهَم لا يُرفض فحسب: فذلك ما ستحصل عليه من الشكل (5, 1)، وهو موضوع المفهوم 2 كلّه. ومع جدول 5×3 تختلف القراءتان شكلًا فيرفع الخطأُ خطأً؛ ومع جدول مربّع لا تختلفان ولا يرفع.

Why is subtracting marks.mean(axis=1) from a square marks table worse than a crash?لماذا طرحُ marks.mean(axis=1) من جدول marks مربّع أسوأ من الانهيار؟

A crash tells you on the line that caused it. This tells you nothing, and the output has the right shape and a believable range, so it survives a glance at the first few rows. The fourth answer is worth refuting precisely: the values are not a transposed version of the right answer, they are arithmetic between quantities that have nothing to do with each other — there is no rearrangement that recovers the intended result. The habit that prevents all of it is to print .shape of both operands before writing a line like this.
الانهيارُ يخبرك في السطر الذي سبّبه. وهذا لا يخبرك بشيء، ومُخرَجه بالشكل الصحيح وبمدى قابل للتصديق، فينجو من نظرة إلى الصفوف الأولى. والجواب الرابع يستحق دحضًا دقيقًا: فالقيم ليست نسخة منقولة من الجواب الصحيح، بل حسابٌ بين كمّيات لا علاقة بينها — ولا إعادةَ ترتيب تستعيد النتيجة المقصودة. والعادةُ التي تمنع ذلك كله أن تطبع .shape للطرفين قبل كتابة سطر كهذا.

Before you startقبل أن تبدأ

Concept 1 — The axis you name is the one that disappearsالمفهوم 1 — المحور الذي تسمّيه هو الذي يختفي

The problemالمشكلة

You want two summaries of the same table: how each subject did, and how each student did. Both are one call to mean, differing by a single digit, and that digit is the one everybody guesses wrong.

تريد ملخّصين للجدول نفسه: كيف أبلت كل مادة، وكيف أبلى كل طالب. وكلاهما استدعاءٌ واحد لـ mean يختلفان برقم واحد، وذلك الرقم هو ما يخمّنه الجميع خطأً.

import numpy as np

marks = np.array([[40., 55., 70.],
                  [60., 65., 90.],
                  [80., 75., 50.]])

print(marks.shape)
print(marks.mean())
print(marks.mean(axis=0), marks.mean(axis=0).shape)
print(marks.mean(axis=1), marks.mean(axis=1).shape)
(3, 3) 65.0 [60. 65. 70.] (3,) [55. 71.66666667 68.33333333] (3,)

The rule that makes this stop being a guessالقاعدة التي تجعل هذا يكفّ عن كونه تخمينًا

The shape is (rows, columns), so axis 0 is rows and axis 1 is columns. The axis you name is the one that is collapsed away. axis=0 eats the rows, which means it runs down each column and leaves one number per column — a subject average. axis=1 eats the columns, running across each row, leaving one number per student.

الشكلُ (الصفوف، الأعمدة)، فالمحور 0 هو الصفوف والمحور 1 هو الأعمدة. والمحورُ الذي تسمّيه هو الذي يُطوى. فـ axis=0 يأكل الصفوف، ومعناه أنه يمشي نزولًا في كل عمود ويترك عددًا لكل عمود — متوسطَ مادة. وaxis=1 يأكل الأعمدة، فيمشي عرضًا في كل صفّ، تاركًا عددًا لكل طالب.

The reliable check is the shape, not the intuition: (3, 3) with axis 0 removed is (3,) — three numbers, one per surviving column.

والفحصُ الموثوق هو الشكل لا الحدس: فـ (3, 3) بإزالة المحور 0 تصير (3,) — ثلاثة أعداد، واحدٌ لكل عمود باقٍ.

The same axis argument works on every reduction, and they all behave identically:

ووسيطُ المحور نفسه يعمل على كل اختزال، وكلُّها تتصرف تمامًا:

print(marks.sum(axis=0))
print(marks.min(axis=1))
print(marks.max())
print(marks.std(axis=0).round(2))
[180. 195. 210.] [40. 60. 50.] 90.0 [16.33 8.16 16.33]

keepdims, and why it existskeepdims ولماذا توجد

Lesson 12's silent disaster happened because mean(axis=1) gave shape (3,), which no longer says which direction it came from. keepdims=True leaves the collapsed dimension in place as a 1, so the shape remembers.

وقعت كارثةُ الدرس 12 الصامتة لأن mean(axis=1) أعطت الشكل (3,) الذي لم يعد يقول من أي اتجاه جاء. وkeepdims=True تُبقي البُعدَ المطويّ في موضعه 1، فيتذكّر الشكل.

print(marks.mean(axis=1).shape)
print(marks.mean(axis=1, keepdims=True).shape)

print(marks - marks.mean(axis=1, keepdims=True))
(3,) (3, 1) [[-15. 0. 15. ] [-11.66666667 -6.66666667 18.33333333] [ 11.66666667 6.66666667 -18.33333333]]

That is the same correct answer as [:, None] gave, reached without the ambiguous shape ever existing. Make it a habit: if a reduction's result is going to be combined with the original array, ask for keepdims=True.

وذلك هو الجوابُ الصحيح نفسه الذي أعطته [:, None]، مبلوغًا دون أن يوجد الشكلُ الملتبس أصلًا. واجعلها عادة: إن كانت نتيجةُ اختزال ستُدمج بالمصفوفة الأصلية فاطلب keepdims=True.

For the usual three-by-three table of marks, what is (marks >= 60).sum(axis=1)?في جدول العلامات المعتاد ثلاثة في ثلاثة، ما (marks >= 60).sum(axis=1)؟

Two rules in sequence, and both have to be right. The comparison gives a (3, 3) mask, and the axis then says which direction to count in — the axis you name is the one that disappears, so axis 1 leaves one number per row. The second option is what axis=0 gives, and on a square table both are three numbers, so the shape will not tell you which one you asked for. The fourth option is .any(axis=1): counting and asking are different questions.
قاعدتان بالتتابع، وكلتاهما يجب أن تصحّ. فالمقارنةُ تعطي قناعًا (3, 3)، ثم يقول المحورُ في أي اتجاه يُعدّ — فالمحور الذي تسمّيه هو الذي يختفي، فيترك المحور 1 عددًا لكل صفّ. والخيار الثاني هو ما تعطيه axis=0، وعلى جدول مربّع كلاهما ثلاثة أعداد، فلن يخبرك الشكل أيّهما طلبت. والخيار الرابع هو .any(axis=1): فالعدُّ والسؤال سؤالان مختلفان.

Exercise 13.1 — A shortlist with two conditionsتمرين 13.1 — قائمةٌ قصيرة بشرطين

Four students, three subjects, and one mark never arrived. Select the rows of students who scored 60 or more in the first subject and have a complete set of marks. No loop, no if, and no np.isnan — the chapter has already given you a way to exclude a gap.

أربعة طلبة وثلاث مواد وعلامةٌ لم تصل أبدًا. اختر صفوف الطلبة الذين نالوا 60 أو أكثر في المادة الأولى ولديهم علامات كاملة. بلا حلقة ولا if ولا np.isnan — فقد أعطاك الفصل سبيلًا لاستثناء الفراغ.

marks = np.array([[40., 55., 70.],
                  [60., np.nan, 90.],
                  [80., 75., 50.],
                  [65., 70., 72.]])
# expected:
# [[80. 75. 50.]
#  [65. 70. 72.]]
Show solutionإظهار الحل 
complete = (marks >= 0).all(axis=1)
strong = marks[:, 0] >= 60

print(complete)
print(strong)
print(marks[complete & strong])
[ True False True True] [False True True True] [[80. 75. 50.] [65. 70. 72.]]

The trick is the one fact about nan that is easy to resent and useful here: every comparison against it is False. So marks >= 0 is false at the gap, and requiring it of every mark in the row excludes exactly the students with a missing mark. np.isnan(marks).any(axis=1) is the version that says what it means, and you should prefer it in real code; this one is worth doing once to make the rule stick.

والحيلةُ هي الواقعةُ الوحيدة عن nan التي يسهل الاستياء منها وهي مفيدة هنا: فكلُّ مقارنة بها False. فـ marks >= 0 كاذبةٌ عند الفراغ، واشتراطُها في كل علامة في الصفّ يستثني بالضبط الطلبةَ ذوي العلامة المفقودة. وnp.isnan(marks).any(axis=1) هي النسخة التي تقول ما تعني، وينبغي أن تُفضّلها في الشفرة الحقيقية؛ وهذه جديرةٌ بأن تُفعل مرة ليثبت القاعدة.

Two masks, one per row each, combined with & — and note that both had to be reduced to one answer per row before they could meet. complete came from a reduction across the columns and strong from a single column; they are the same shape, (4,), which is what makes the & legal and the row selection correct.

قناعان، في كلٍّ مدخلٌ لكل صفّ، مجموعان بـ & — ولاحظ أن كليهما وجب أن يُخفَّض إلى جوابٍ لكل صفّ قبل أن يتلاقيا. فـ complete جاء من تخفيضٍ على الأعمدة وstrong من عمودٍ واحد؛ وهما بالشكل نفسه (4,)، وذلك ما يجعل & مشروعةً واختيارَ الصفوف صحيحًا.

Concept 2 — A mask is a question answered for every elementالمفهوم 2 — القناع سؤالٌ مُجابٌ لكل عنصر

The problemالمشكلة

List every mark of 60 or more, count them, and cap anything above 95. Written with a loop that is three loops and two counters; written with masks it is three lines with no if anywhere.

اسرد كل علامة 60 فأكثر، وعدّها، واحصر ما فوق 95. ومكتوبًا بحلقة فهو ثلاث حلقات وعدّادان؛ ومكتوبًا بالأقنعة فهو ثلاثة أسطر بلا if في أي موضع.

marks = np.array([40, 55, 70, 85, 100])

passed = marks >= 60
print(passed)
print(marks[passed])
print(passed.sum())
[False False True True True] [ 70 85 100] 3

Three separate ideas, each worth stating. A comparison produces a mask — one True or False per element, the same shape as the array. Indexing with a mask selects the elements where it is True. And summing a mask counts them, because True adds as 1 — which is why you will see .sum() used to count things all through the rest of this course.

ثلاث أفكار منفصلة، كلٌّ جديرة بالقول. فالمقارنةُ تُنتج قناعًا — True أو False لكل عنصر، بشكل المصفوفة نفسه. والفهرسةُ بقناع تختار العناصر التي هو فيها True. وجمعُ القناع يعدّها، لأن True تُجمع 1 — ولهذا سترى .sum() مستعملةً للعدّ في بقية هذا المقرر كله.

Combining conditions: & and |, never andجمع الشروط: & و| ولا and أبدًا

print(marks[(marks > 50) & (marks < 90)])
print(marks[(marks < 50) | (marks > 90)])

print(marks[(marks > 50) and (marks < 90)])
[55 70 85] [ 40 100] ValueError: The truth value of an array with more than one element is ambiguous. Use a.any() or a.all()

The error is being helpful, if you read it slowly. and wants to decide whether the whole left side is true or false, so that it can decide whether to look at the right side — and an array of five answers is neither. & has no such ambition: it combines the two masks element by element. The brackets are not optional: & binds more tightly than >, so without them Python tries 50 & marks first.

الخطأُ يساعدك إن قرأته متمهلًا. فـ and تريد أن تقرّر هل الطرف الأيسر كله صحيح أم خطأ، لتقرّر هل تنظر إلى الأيمن — ومصفوفةٌ بخمسة أجوبة ليست هذا ولا ذاك. أما & فلا طموح لها في ذلك: إنما تجمع القناعين عنصرًا عنصرًا. والقوسان ليسا اختياريين: فـ & أشدُّ ارتباطًا من >، فبلا قوسين تجرّب بايثون 50 & marks أولًا.

Selecting rows of a tableاختيار صفوف جدول

This is the form you will use for the rest of the course: build a mask from one column, then use it to pick whole rows.

وهذه هي الصيغة التي ستستعملها بقية المقرر: ابنِ قناعًا من عمود ثم استعمله لانتقاء صفوف كاملة.

marks = np.array([[40., 55., 70.],
                  [60., 65., 90.],
                  [80., 75., 50.]])

strong = marks[:, 0] >= 60
print(strong)
print(marks[strong])
print(marks[strong].shape)
[False True True] [[60. 65. 90.] [80. 75. 50.]] (2, 3)

The mask has one entry per row, because it was built from a column, and indexing the table with it keeps those rows whole. Note the result is (2, 3), not a flat list of six numbers — the rows stayed rows, so a student's three subjects are still together.

للقناع مدخلٌ لكل صفّ، لأنه بُني من عمود، وفهرسةُ الجدول به تُبقي تلك الصفوف كاملة. ولاحظ أن النتيجة (2, 3) لا قائمةً مسطّحة من ستة أعداد — فقد بقيت الصفوف صفوفًا، فمواد الطالب الثلاث لا تزال معًا.

np.where: choose per elementnp.where: اختر لكل عنصر

flat = np.array([40, 55, 70, 85, 100])

print(np.where(flat >= 60, "pass", "fail"))
print(np.where(flat > 90, 90, flat))
['fail' 'fail' 'pass' 'pass' 'pass'] [40 55 70 85 90]

Read it as "where the mask is true take the second argument, otherwise the third" — an if/else applied to every element at once. It returns a new array, which is the difference from flat[flat > 90] = 90 in Lesson 11, which writes into the original.

اقرأها «حيث يكون القناع صحيحًا خذ الوسيط الثاني، وإلا فالثالث» — وهي if/else مطبَّقة على كل عنصر دفعةً. وتُعيد مصفوفة جديدة، وذلك هو الفرق عن flat[flat > 90] = 90 في الدرس 11 التي تكتب في الأصل.

One missing mark poisons the averageعلامةٌ مفقودة واحدة تسمّم المتوسط

marks = np.array([40., np.nan, 70.])

print(marks.mean())
print(np.nanmean(marks))
print(np.isnan(marks).sum())
nan 55.0 1

An array has one type, so a missing mark cannot be None in a float array; it is nan. Any arithmetic touching it gives nan, so one gap turns the whole class average into nan — loudly, which is the kindness. An average that quietly skipped the gap would be the average of a different class from the one you asked about. Decide deliberately: np.nanmean to skip, or find them with np.isnan and deal with them. Never marks == np.nan, which is False everywhere and finds nothing, silently.

للمصفوفة نوعٌ واحد، فلا تكون العلامةُ المفقودة None في مصفوفة عشرية؛ بل nan. وأي حساب يمسّها يعطي nan، فتحوّل فجوةٌ واحدة متوسطَ الصفّ كله إلى nan — بصوت عالٍ، وذلك هو اللطف. فمتوسطٌ يتخطى الفجوة بصمت سيكون متوسط صفٍّ غير الذي سألت عنه. قرّر متعمدًا: np.nanmean للتخطي، أو جدها بـ np.isnan وعالجها. ولا تكتب marks == np.nan أبدًا، فهي False في كل موضع ولا تجد شيئًا بصمت.

Exercise 13.2 — Who passed everything?تمرين 13.2 — من نجح في كل شيء؟

Select the rows of students who scored 60 or more in every subject. One mask, built with a reduction, then used to index. Think about which axis.

اختر صفوف الطلبة الذين نالوا 60 فأكثر في كل مادة. قناعٌ واحد يُبنى باختزال ثم يُستعمل للفهرسة. وفكّر في أي محور.

marks = np.array([[40., 55., 70.],
                  [60., 65., 90.],
                  [80., 75., 50.]])
# expected:
# [[60. 65. 90.]]
Show solutionإظهار الحل 
all_passed = (marks >= 60).all(axis=1)
print(all_passed)
print(marks[all_passed])
[False True False] [[60. 65. 90.]]

Two steps worth separating. marks >= 60 is a (3, 3) mask, one answer per mark. .all(axis=1) then collapses the columns, asking "were they all true across this row?" and leaving one answer per student — shape (3,). Use .any(axis=1) instead and you get students who passed at least one; use axis=0 and you get an answer per subject, which is a different question entirely.

خطوتان تستحقان الفصل. فـ marks >= 60 قناعٌ (3, 3)، جوابٌ لكل علامة. ثم تطوي .all(axis=1) الأعمدةَ سائلةً «أكانت كلها صحيحة عرض هذا الصفّ؟» وتترك جوابًا لكل طالب — شكله (3,). واستعمل .any(axis=1) بدلًا منها تنل الطلبة الناجحين في واحدة على الأقل؛ واستعمل axis=0 تنل جوابًا لكل مادة، وذلك سؤال مختلف تمامًا.

Exercise 13.3 — A report with no loopsتمرين 13.3 — تقريرٌ بلا حلقات

From the table, print: the hardest subject (lowest average), how many marks in the whole table are below 60, and the class average with any missing marks skipped.

من الجدول، اطبع: أصعب مادة (أدنى متوسط)، وكم علامة في الجدول كله دون 60، ومتوسطَ الصفّ مع تخطي أي علامات مفقودة.

subjects = np.array(["maths", "arabic", "science"])
marks = np.array([[40., 55., 70.],
                  [60., np.nan, 90.],
                  [80., 75., 50.]])
Show solutionإظهار الحل 
means = np.nanmean(marks, axis=0)
print("hardest subject:", subjects[means.argmin()], means.round(1))
print("marks below 60:", (marks < 60).sum())
print("class average:", round(np.nanmean(marks), 2))
hardest subject: maths [60. 65. 70.] marks below 60: 3 class average: 65.0

Three things to take away. argmin gives the position of the smallest, not the value, which is exactly what you need to look up a name in another array. (marks < 60).sum() counts over the whole table at once because no axis was named. And the nan is simply not counted by < 60 — a comparison against nan is False, so the missing mark is neither a pass nor a fail, which is honest.

ثلاثة أمور تأخذها. فـ argmin تعطي موضع الأصغر لا قيمته، وهو بالضبط ما تحتاجه للبحث عن اسم في مصفوفة أخرى. و(marks < 60).sum() تعدّ على الجدول كله دفعةً لأنه لم يُسمَّ محور. وnan لا تُعدّ ببساطة بـ < 60 — فالمقارنة بـ nan هي False، فالعلامةُ المفقودة ليست نجاحًا ولا رسوبًا، وذلك صادق.

A table has shape (30, 4) — thirty students, four subjects. Which call gives one average per subject?جدولٌ شكله (30, 4) — ثلاثون طالبًا وأربع مواد. فأي استدعاء يعطي متوسطًا لكل مادة؟

The second answer is the intuition almost everyone has, and it is exactly backwards: naming an axis removes it rather than keeping it. The shape is the check that never lies — (30, 4) with axis 0 gone is (4,), four numbers, one per subject, while axis 1 would give (30,), one per student. This table is not square, so a mistake here produces an obviously wrong length; on a square table it would not, which is Lesson 12's disaster.
الجواب الثاني هو حدسُ الجميع تقريبًا، وهو مقلوب بالضبط: فتسميةُ محور تزيله لا تُبقيه. والشكلُ هو الفحص الذي لا يكذب — فـ (30, 4) بذهاب المحور 0 تصير (4,)، أربعة أعداد لكل مادة، بينما المحور 1 سيعطي (30,)، واحدًا لكل طالب. وهذا الجدول ليس مربّعًا، فالخطأ هنا يُنتج طولًا خاطئًا بيّنًا؛ وعلى جدول مربّع لن يفعل، وتلك كارثةُ الدرس 12.

Why does marks[(marks > 50) and (marks < 90)] raise a ValueError when & works?لماذا ترفع marks[(marks > 50) and (marks < 90)] خطأ ValueError بينما تعمل &؟

The message names the problem precisely once you know what to look for: "the truth value of an array with more than one element is ambiguous". It is asking you for one answer and you have given it five. Note the brackets round each comparison are still required with & — & binds more tightly than >, so leaving them off makes Python attempt 50 & marks.
الرسالةُ تسمّي المشكلة بدقة متى عرفت ما تبحث عنه: «قيمةُ الصدق لمصفوفة بأكثر من عنصر ملتبسة». فهي تطلب منك جوابًا واحدًا وقد أعطيتها خمسة. ولاحظ أن القوسين حول كل مقارنة لا يزالان لازمَين مع & — فـ & أشدُّ ارتباطًا من >، فتركُهما يجعل بايثون تحاول 50 & marks.
