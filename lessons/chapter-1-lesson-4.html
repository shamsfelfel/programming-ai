Lesson 4

Abstraction & Clean Interfacesالتجريد والواجهات

By the end of this lesson you will be able to replace the inside of a class completely — a tuple becomes fields, a new field appears — without a single caller noticing, and you will know how to make Python refuse to create an object that has not kept the promise its base class made.

بنهاية هذا الدرس ستكون قادرًا على استبدال داخل الصنف استبدالًا كاملًا — فيصبح الـ tuple حقولًا، ويظهر حقل جديد — دون أن يلاحظ مستدعٍ واحد، وستعرف كيف تجعل بايثون ترفض إنشاء كائن لم يفِ بالوعد الذي قطعه صنفه الأساس.

The settingالإطار

A small shop in the neighbourhood runs a solar charging point. People leave a power bank or a car battery on the shelf, it charges from the panels on the roof, and they pay by the minute. One Python file prints receipts, totals the day, lists what is still charging, and sends each customer a message when their battery is ready.

دكان صغير في الحي يشغّل نقطة شحن تعمل بالطاقة الشمسية. يترك الناس بطارية متنقلة أو بطارية سيارة على الرف، فتُشحن من الألواح على السطح، ويدفعون بالدقيقة. وملف بايثون واحد يطبع الإيصالات، ويجمع حصيلة اليوم، ويسرد ما لا يزال يُشحن، ويرسل إلى كل عميل رسالة عندما تجهز بطاريته.

Lesson 3 was about who is allowed to change an attribute. This lesson is about something narrower and, in a growing program, more expensive: how much a caller is allowed to know. Properties are behind us — we will use them without explaining them again.

كان الدرس 3 عن من يُسمح له بـتغيير خاصية. وهذا الدرس عن أمر أضيق، وأغلى ثمنًا في برنامج آخذ في النمو: كم يُسمح للمستدعي أن يعرف. والـ properties صارت خلفنا — سنستخدمها دون أن نشرحها من جديد.

Concept 1 — A small public promise, a free hand insideالمفهوم 1 — وعد عام صغير، ويد حرة في الداخل

The problemالمشكلة

A charge session is stored as a tuple: (customer, start_min, end_min), where the times are minutes since the shop opened and end_min is None while the battery is still on the shelf. Four different functions take one of these tuples apart. Each one writes s[1] and s[2] by hand, each one re-derives the minutes with its own copy of the same subtraction, and one of them unpacks with name, start, end = s.

تُخزَّن جلسة الشحن كـ tuple: (customer, start_min, end_min)، حيث الأوقات دقائق منذ افتتاح الدكان، وend_min تساوي None ما دامت البطارية على الرف. وأربع دوال مختلفة تفكّك واحدًا من هذه الـ tuples. كل واحدة تكتب s[1] وs[2] بيدها، وكل واحدة تعيد استخراج الدقائق بنسختها الخاصة من الطرح نفسه، وإحداها تفكّك بـ name, start, end = s.

Then the shop buys a bigger inverter. When the sun drops, charging pauses automatically, and the owner refuses to bill customers for paused time. So the row needs a fourth value, paused_minutes, and it belongs with the other timing numbers: (customer, start_min, paused_minutes, end_min).

ثم يشتري الدكان عاكسًا أكبر. فعندما تنخفض الشمس يتوقف الشحن تلقائيًا، ويرفض صاحب الدكان أن يحاسب العملاء على وقت التوقف. فيحتاج السطر إلى قيمة رابعة هي paused_minutes، ومكانها بين أرقام التوقيت الأخرى: (customer, start_min, paused_minutes, end_min).

Three of the four functions keep running after the change, and every number they print is wrong. The fourth crashes. The owner reads the receipts first.

ثلاث من الدوال الأربع تواصل العمل بعد التغيير، وكل رقم تطبعه خاطئ. والرابعة تنهار. وصاحب الدكان يقرأ الإيصالات أولًا.

The starting codeالكود الابتدائي

This is station.py as the shop runs it today. Before you read the output, count how many times the number 2 appears as an index.

هذا ملف station.py كما يشغّله الدكان اليوم. وقبل أن تقرأ الناتج، أحصِ كم مرة يظهر الرقم 2 كفهرس.

# (customer, start_min, end_min), minutes since opening
sessions = [("Mahmoud", 5, 65),
            ("Nidal", 8, 98),
            ("Umm Rami", 12, 132),
            ("Khaled", 20, None)]

RATE = 0.50      # shekel per minute
NOW = 140        # minutes since the shop opened


def receipt_line(s):
    end = s[2] if s[2] is not None else NOW
    minutes = end - s[1]
    return f"{s[0]:10} {minutes:4} min {minutes * RATE:7.2f}"


def day_total(sessions):
    total = 0.0
    for s in sessions:
        end = s[2] if s[2] is not None else NOW
        total += (end - s[1]) * RATE
    return total


def running_now(sessions):
    return [s[0] for s in sessions if s[2] is None]


def sms_text(s):
    name, start, end = s
    minutes = (end if end is not None else NOW) - start
    return f"{name}: your battery is ready, {minutes} min"


for s in sessions:
    print(receipt_line(s))
print("still charging:", running_now(sessions))
print(f"day total: {day_total(sessions):.2f}")
print(sms_text(sessions[0]))

The crash is the good newsالانهيار هو الخبر الجيد

Look at the order of the damage. sms_text failed loudly, and it was the only honest function in the file — unpacking three names from a four-value tuple is something Python can see, so it stopped. The other three said nothing at all.

انظر إلى ترتيب الضرر. فـ sms_text فشلت بصوت عالٍ، وكانت الدالة الصريحة الوحيدة في الملف — فتفكيك ثلاثة أسماء من tuple بأربع قيم أمر تستطيع بايثون رؤيته، فتوقفت. أما الثلاث الأخريات فلم تقل شيئًا إطلاقًا.

Mahmoud's receipt says he owes −2.50 shekels, because s[2] now reads paused_minutes — zero for him — so the arithmetic became 0 - 5. Nidal paused for 12 minutes, so his receipt says 4 minutes and 2 shekels instead of 78 minutes and 39. The day total is a negative number. A wrong index is not an error in Python. It is a different, equally valid number.

Diagnosisتشخيص العيب

Ask what each caller actually wanted to know. receipt_line wanted the minutes used and the cost. day_total wanted the cost. running_now wanted a yes-or-no: is this session still running? sms_text wanted the minutes used. Not one of them wanted a tuple, an index, or a subtraction.

اسأل ما الذي أراد كل مستدعٍ أن يعرفه فعلًا. فـ receipt_line أرادت الدقائق المستهلكة والتكلفة. وday_total أرادت التكلفة. وrunning_now أرادت نعم أو لا: هل هذه الجلسة لا تزال تعمل؟ وsms_text أرادت الدقائق المستهلكة. ولم تُرد أي واحدة منها tuple ولا فهرسًا ولا طرحًا.

But a tuple has no way to answer a question; it can only be taken apart. So the internal shape of the data leaked into the public surface, and from there into every caller. By the time the shape changed, the shape was not a private decision any more — it was a contract signed in four places by people who never read it.

لكن الـ tuple لا سبيل له إلى الإجابة عن سؤال؛ فلا يمكن إلا تفكيكه. ومن ثم تسرّبت البنية الداخلية للبيانات إلى السطح العام، ومنه إلى كل مستدعٍ. وحين تغيّرت البنية لم تكن البنية قرارًا خاصًا بعد — بل عقدًا موقّعًا في أربعة مواضع من أناس لم يقرأوه قط.

The conversion — publish the answers, hide the shapeالتحويل — انشر الإجابات واخفِ البنية

Write a class whose public surface is exactly the four things the callers asked for, and nothing else: customer, minutes_used(), cost(), is_running. To prove the point, the first version keeps the tuple inside, untouched — the same data, the same arithmetic, just moved behind a door.

اكتب صنفًا سطحه العام هو بالضبط الأمور الأربعة التي طلبها المستدعون، ولا شيء غيرها: customer وminutes_used() وcost() وis_running. ولإثبات الفكرة، تحتفظ النسخة الأولى بالـ tuple في الداخل بلا مساس — البيانات نفسها والحساب نفسه، لكن منقولًا خلف باب.

RATE = 0.50
NOW = 140


class ChargeSession:
    def __init__(self, customer, start_min, end_min=None):
        # internals, version 1: one tuple, like the old rows
        self._row = (customer, start_min, end_min)

    @property
    def customer(self):
        return self._row[0]

    @property
    def is_running(self):
        return self._row[2] is None

    def minutes_used(self):
        end = self._row[2]
        if end is None:
            end = NOW
        return end - self._row[1]

    def cost(self):
        return self.minutes_used() * RATE


# ---- THE CALLER (never changes below this line) ----
def receipt_line(s):
    return (f"{s.customer:10} {s.minutes_used():4} min"
            f" {s.cost():7.2f}")


def day_total(book):
    return sum(s.cost() for s in book)


def running_now(book):
    return [s.customer for s in book if s.is_running]


def sms_text(s):
    return (f"{s.customer}: your battery is ready,"
            f" {s.minutes_used()} min")

The same request, the second timeالطلب نفسه، في المرة الثانية

Now the inverter arrives again. This time the internals change twice over: the tuple is thrown away for named fields, and paused_minutes is added. Every line below the caller comment is pasted from the previous listing without one keystroke of editing.

الآن يصل العاكس من جديد. وهذه المرة يتغيّر الداخل تغيّرين: فيُطرح الـ tuple جانبًا لصالح حقول مسمّاة، وتُضاف paused_minutes. وكل سطر تحت تعليق المستدعي ملصوق من القائمة السابقة بلا ضغطة مفتاح واحدة من التعديل.

RATE = 0.50
NOW = 140


class ChargeSession:
    def __init__(self, customer, start_min, end_min=None,
                 paused_minutes=0):
        # internals, version 2: named fields, plus the new
        # paused_minutes the team asked for
        self.customer = customer
        self._start = start_min
        self._end = end_min
        self._paused = paused_minutes

    @property
    def is_running(self):
        return self._end is None

    def minutes_used(self):
        end = self._end if self._end is not None else NOW
        return end - self._start - self._paused

    def cost(self):
        return self.minutes_used() * RATE

Also notice what one of the internal edits was: customer stopped being a property and became a plain attribute, because once the tuple was gone there was nothing left to translate. That is a change to the class's own code, and the callers still write s.customer. They could not tell the difference if they tried.

ولاحظ أيضًا ما كان أحد التعديلات الداخلية: فقد كفّت customer عن كونها property وصارت خاصية عادية، لأنه بعد زوال الـ tuple لم يبقَ ما يُترجَم. وهذا تغيير في كود الصنف نفسه، والمستدعون لا يزالون يكتبون s.customer. ولن يستطيعوا تمييز الفرق لو حاولوا.

Interface and implementation — say it once, clearlyالواجهة والتنفيذ — قُلها مرة واحدة بوضوح

The interface is what the object promises: the names a caller may use and what they mean. The implementation is how the object keeps that promise: the attributes, the data structures, the arithmetic. minutes_used() is interface. self._start, self._paused, and the subtraction between them are implementation.

الـ واجهة هي ما يَعِد به الكائن: الأسماء التي يجوز للمستدعي استخدامها ومعانيها. والـ تنفيذ هو كيف يفي الكائن بذلك الوعد: الخصائص وبنى البيانات والحساب. فـ minutes_used() واجهة. وself._start وself._paused والطرح بينهما تنفيذ.

Everything you may change freely tomorrow is implementation. Everything you may not change without breaking somebody is interface. Abstraction is the work of deciding which is which — and the smaller you keep the second group, the more freedom you keep for yourself.

كل ما يجوز لك تغييره بحرية غدًا تنفيذ. وكل ما لا يجوز لك تغييره دون أن تكسر أحدًا واجهة. والتجريد هو عمل تحديد أيّهما أيّ — وكلما أصغرت المجموعة الثانية، أبقيت لنفسك حرية أكبر.

Why minutes_used() has brackets and is_running does notلماذا لـ minutes_used() أقواس ولـ is_running لا

Nothing forces the choice; it is a signal to the reader. is_running reads like a state the object is simply in, so it is a property. minutes_used() and cost() read like a figure being worked out, so they keep their brackets. Pick a convention and hold it across a class — but remember the Lesson 3 lesson underneath it: whichever you choose, the caller cannot see how the answer is produced, and that is the part that matters.

لا شيء يفرض الاختيار؛ فهو إشارة إلى القارئ. فـ is_running تُقرأ كحالة يكون فيها الكائن ببساطة، فهي property. وminutes_used() وcost() تُقرآن كرقم يُستخرج، فتبقى لهما أقواسهما. فاختر اتفاقًا والتزم به في الصنف كله — لكن تذكّر درس الدرس 3 الكامن تحته: فأيًّا اخترت، لا يستطيع المستدعي أن يرى كيف تُنتَج الإجابة، وهذا هو الجزء المهم.

Second example — a clinic water tank that changed its gaugeمثال ثانٍ — خزان ماء في عيادة غيّر مقياسه

A clinic shows its water level on a screen in the waiting room. The old tank reported litres; the new roof tank has a float gauge that reports depth in centimetres instead. Two completely different internals, one promise — litres_left() and is_low() — and one display function that works for both without knowing which it is holding.

تعرض عيادة مستوى ماءها على شاشة في غرفة الانتظار. والخزان القديم كان يُبلّغ باللترات؛ أما خزان السطح الجديد فله مقياس عوّامة يُبلّغ بالعمق بالسنتيمترات. فداخلان مختلفان تمامًا، ووعد واحد — litres_left() وis_low() — ودالة عرض واحدة تعمل لكليهما دون أن تعرف أيّهما تحمل.

class TankV1:                 # internals: litres
    def __init__(self, litres):
        self._litres = litres

class PrepaidCard:
    def __init__(self, name, paid, used=0.0):
        self.name = name
        self._paid = paid
        self._used = used

    def balance(self):
        return round(self._paid - self._used, 2)

    def is_low(self):
        return self.balance() < 5

    def charge(self, amount):
        if amount > self.balance():
            raise ValueError(f"only {self.balance()} left")
        self._used += amount
        return self.balance()

Step 2 — ABC and @abstractmethod: write the promise downالخطوة 2 — ABC و@abstractmethod: اكتب الوعد

An abstract base class is a class whose job is to state a requirement rather than to do work. Inherit from ABC, mark a method with @abstractmethod, and Python will refuse to create an object of any subclass that has not provided that method.

الـ صنف الأساس المجرَّد صنف مهمته أن يقرّر مطلبًا لا أن ينجز عملًا. فورّث من ABC، وعلّم دالة بـ @abstractmethod، وسترفض بايثون إنشاء كائن من أي صنف مشتق لم يوفّر تلك الدالة.

The three working classes gain four characters each — (Notifier). The intern's class gains the same four, and that is enough.

تكسب الأصناف الثلاثة العاملة أربعة محارف لكل منها — (Notifier). وصنف المتدرب يكسب الأربعة نفسها، وهذا يكفي.

Nothing was fixed and nothing was renamed — the ABC only refuses to build the object, so TelegramNotifier() now raises TypeError on the line that creates it, long before any customer is involved. Step 3 — a concrete method on top of the promiseالخطوة 3 — دالة ملموسة فوق الوعد

A base class does not have to be only requirements. It can also hold finished code that uses the requirement. The shop's message wording, its sign-off, and its sent counter are the same whatever the channel — so write them once on Notifier, calling the abstract send() that each subclass supplies.

ليس على صنف الأساس أن يكون مطالب فقط. بل يستطيع أن يحمل أيضًا كودًا جاهزًا يستخدم المطلب. فصياغة رسالة الدكان وخاتمتها وعدّاد ما أُرسل هي نفسها أيًّا كانت القناة — فاكتبها مرة واحدة على Notifier، مستدعيةً send() المجرَّدة التي يوفّرها كل صنف مشتق.

from abc import ABC, abstractmethod


class Notifier(ABC):
    shop = "Nour Charging Point"

    def __init__(self):
        self.sent_count = 0

    @abstractmethod
    def send(self, to, text):
        """Deliver one message. Every Notifier must do this."""

    # concrete method, built on top of the promise
    def notify_done(self, customer, minutes):
        text = (f"{customer['name']}, your battery is ready"
                f" after {minutes} min. {self.shop}")

        text = (f"{customer['name']}, only {shekels:.2f} ILS"

        self.sent_count += 1

Duck typing — and when the ABC is worth the ceremonyالبطّية في التنميط — ومتى يستحق الـ ABC تكلّفه

Python does not require the ABC. charging_done never asked what type it was given; it called send(). Anything with a send(to, text) works, related to Notifier or not — this is duck typing: if it has send(), it is near enough a notifier.

بايثون لا تشترط الـ ABC. فـ charging_done لم تسأل يومًا عن نوع ما أُعطيت؛ بل استدعت send(). فأي شيء فيه send(to, text) يعمل، سواء كان ذا صلة بـ Notifier أم لا — وهذا هو التنميط البطّي: فإن كان فيه send()، فهو قريب بما يكفي من مُرسِل.

So: duck typing for small, local, obvious cases — two implementations in one file, a stand-in in a test. The ABC when the promise is written by one person and kept by others: when subclasses arrive from a different file or a different week, when forgetting the method would only surface in front of a customer, or when there is shared behaviour like notify_done() to hand out. The ABC buys you an early, named error. If nobody would ever get the promise wrong, you are paying for nothing.

هكذا تختبر إشعارات الدكان دون إرسال رسالة قصيرة حقيقية واحدة، ولم يُحتَج إلى صنف أساس لذلك. إذن: التنميط البطّي للحالات الصغيرة المحلية البيّنة — تنفيذان في ملف واحد، أو بديل في اختبار. والـ ABC حين يكتب الوعدَ واحد ويفي به آخرون: حين تأتي الأصناف المشتقة من ملف آخر أو أسبوع آخر، وحين لا يظهر نسيان الدالة إلا أمام عميل، أو حين يكون هناك سلوك مشترك كـ notify_done() ليُوزَّع. فالـ ABC يشتري لك خطأً مبكرًا مسمّى. وإن لم يكن أحد ليخطئ في الوعد يومًا، فأنت تدفع مقابل لا شيء.

Note also what this lesson is not about. Nothing above chose between channels at run time based on the object's type, and that question — handing different objects to the same code and watching each behave in its own way — is Lesson 6. Here the point is only that the promise has a written name.

ولاحظ أيضًا ما ليس هذا الدرس عنه. فلم يختر شيء مما سبق بين القنوات وقت التشغيل بناءً على نوع الكائن، وذلك السؤال — تسليم كائنات مختلفة إلى الكود نفسه ومراقبة كلٍّ منها يتصرف بطريقته — هو الدرس 6. وهنا المقصود فقط أن للوعد اسمًا مكتوبًا.

Different domain, same principle in two lines of code. A reporting tool has to write the day's rows somewhere. ReportExporter promises one thing — export(rows) returns a string — and the function that writes the report never learns whether it is holding CSV or plain text.

مجال مختلف، والمبدأ نفسه في سطرين من الكود. أداة تقارير عليها أن تكتب أسطر اليوم في مكان ما. فـ ReportExporter يَعِد بأمر واحد — أن export(rows) تعيد نصًا — والدالة التي تكتب التقرير لا تعرف قط هل تحمل CSV أم نصًا عاديًا.

from abc import ABC, abstractmethod


class ReportExporter(ABC):
    @abstractmethod
    def export(self, rows):
        """Turn rows into one string in some format."""


class CsvExporter(ReportExporter):
    def export(self, rows):
        return "\n".join(",".join(str(c) for c in row)
                         for row in rows)


class TextExporter(ReportExporter):
    def export(self, rows):
        return "\n".join(f"{str(r[0]):10}{str(r[1]):>5}"
                         f"{str(r[2]):>9}" for r in rows)


# the caller never learns which format it is getting
def daily_report(exporter, rows, path):
    text = exporter.export(rows)
    print(f"--- writing {path} ---")
    print(text)


rows = [("customer", "min", "cost"),
        ("Mahmoud", 60, 30.0),
        ("Nidal", 78, 39.0)]

daily_report(CsvExporter(), rows, "day.csv")
daily_report(TextExporter(), rows, "day.txt")
--- writing day.csv --- customer,min,cost Mahmoud,60,30.0 Nidal,78,39.0 --- writing day.txt --- customer min cost Mahmoud 60 30.0 Nidal 78 39.0

The two outputs could not look less alike, and daily_report is the same three lines for both. Adding an HTML or JSON exporter tomorrow means writing one class with one method — daily_report does not open. That is the whole promise of an interface, stated in the smallest possible example.

الناتجان لا يمكن أن يكونا أقل تشابهًا، وdaily_report هي الأسطر الثلاثة نفسها لكليهما. وإضافة مُصدِّر HTML أو JSON غدًا تعني كتابة صنف واحد بدالة واحدة — وdaily_report لا تُفتح. وهذا هو وعد الواجهة كله، مقولًا في أصغر مثال ممكن.

from abc import ABC, abstractmethod


class SessionLog(ABC):
    @abstractmethod
    def write(self, label, minutes):
        """Store one finished session."""

    def write_many(self, pairs):
        for label, minutes in pairs:
            self.write(label, minutes)
        return len(pairs)


class ShelfLog(SessionLog):
    def __init__(self):
        self.rows = []

    def write(self, label, minutes):
        self.rows.append((label, minutes))


class PaperLog(SessionLog):
    def write(self, label, minutes):
        print(f"paper: {label} ran {minutes} min")


class NullLog(SessionLog):
    def write(self, label, minutes):
        pass


day = [("A1", 60), ("A2", 78), ("A3", 120)]

for log in [ShelfLog(), PaperLog(), NullLog()]:
    n = log.write_many(day)
    print(f"{type(log).__name__}: {n} rows")
ShelfLog: 3 rows paper: A1 ran 60 min paper: A2 ran 78 min paper: A3 ran 120 min PaperLog: 3 rows NullLog: 3 rows

Key takeawaysالخلاصة

  • The interface is what the object promises; the implementation is how it keeps the promise. Abstraction is deciding which is which — and keeping the first list short, because everything on it is frozen and everything off it is yours to change.الـ واجهة ما يَعِد به الكائن؛ والـ تنفيذ كيف يفي بالوعد. والتجريد هو تحديد أيّهما أيّ — وإبقاء القائمة الأولى قصيرة، لأن كل ما فيها مجمَّد وكل ما خارجها ملكك تغيّره.
  • Publish answers, not data. The callers wanted minutes, a cost and a yes-or-no; they got a tuple, so each one wrote its own arithmetic and the internal shape became a contract signed in four places.انشر الإجابات لا البيانات. فالمستدعون أرادوا دقائق وتكلفة ونعم أو لا؛ فحصلوا على tuple، فكتب كل واحد حسابه الخاص وصارت البنية الداخلية عقدًا موقّعًا في أربعة مواضع.
  • A leaked internal shape fails silently. Shifting a tuple field turned a 60-minute receipt into −2.50 shekels and emptied the "still charging" list, with no error at all; only the one function that unpacked into named variables raised ValueError, because unpacking states how many values there are and indexing states nothing.البنية الداخلية المتسرّبة تفشل بصمت. فإزاحة حقل في tuple حوّلت إيصال 60 دقيقة إلى −2.50 شيكل وأفرغت قائمة «لا يزال يُشحن» بلا أي خطأ؛ ولم ترفع ValueError إلا الدالة الواحدة التي فكّكت إلى متغيرات مسمّاة، لأن التفكيك يقرّر عدد القيم والفهرسة لا تقرّر شيئًا.
  • The test of a good interface: you can describe the object to a colleague without naming a single data structure. If you cannot, the structure is part of your public surface whether you meant it to be or not.اختبار الواجهة الجيدة: أن تستطيع وصف الكائن لزميل دون تسمية بنية بيانات واحدة. فإن لم تستطع، فالبنية جزء من سطحك العام، قصدت ذلك أو لم تقصد.
  • Let the class use its own interface internally — state_text() calls self.percent(), cost() calls self.minutes_used(). Then a rewrite of the storage has one line to fix, not several.دع الصنف يستخدم واجهته الخاصة داخليًا — فـ state_text() تستدعي self.percent()، وcost() تستدعي self.minutes_used(). فتكون لإعادة كتابة التخزين سطر واحد لإصلاحه لا عدة أسطر.
  • Agreeing on one method name across classes — send(to, text) — deletes the if/elif chain, because the caller stops choosing a function and starts asking an object. But the agreement alone is unenforced: a class with deliver instead is created happily and raises AttributeError only when called.الاتفاق على اسم دالة واحد في الأصناف — send(to, text) — يمحو سلسلة if/elif، لأن المستدعي يكفّ عن اختيار دالة ويبدأ بسؤال كائن. لكن الاتفاق وحده غير مفروض: فصنف فيه deliver بدلًا منها يُنشَأ بارتياح ولا يرفع AttributeError إلا عند الاستدعاء.
  • class Notifier(ABC) with @abstractmethod def send(...) writes the promise down. An incomplete subclass then fails at TelegramNotifier() with TypeError: Can't instantiate abstract class … without an implementation for abstract method 'send' — the error moved from the customer's side of the counter to the programmer's.class Notifier(ABC) مع @abstractmethod def send(...) تكتب الوعد. فيفشل الصنف المشتق الناقص حينئذ عند TelegramNotifier() بـ TypeError: Can't instantiate abstract class … without an implementation for abstract method 'send' — فانتقل الخطأ من جهة العميل من الطاولة إلى جهة المبرمج.
  • The ABC enforces the method's name, not its full shape. A subclass with def send(self, chat_id, body, retries) is still instantiable and will still fail on the call, so the base class is a reminder, not a type checker.الـ ABC يفرض اسم الدالة لا بنيتها الكاملة. فصنف مشتق فيه def send(self, chat_id, body, retries) لا يزال قابلًا للإنشاء وسيفشل عند الاستدعاء، فصنف الأساس تذكير لا فاحص أنواع.
  • A concrete method on the base built on the abstract one — notify_done() calling send() — hands shared behaviour to every subclass for free. That shape is the template method: finished code calling down into code the subclass must supply.دالة ملموسة في الأساس مبنية على المجرَّدة — notify_done() تستدعي send() — تمنح كل صنف مشتق سلوكًا مشتركًا مجانًا. وهذه البنية هي الدالة القالب: كود جاهز يستدعي نزولًا كودًا يجب أن يوفّره الصنف المشتق.
  • Duck typing is the lighter alternative: anything with send() works, inheritance or not — which is how FakeNotifier captured messages in a test without sending one. Use it for few, local, obvious implementations; reach for the ABC when others will keep the promise, when forgetting it would only surface in production, or when there is shared behaviour to hand out.التنميط البطّي هو البديل الأخف: فأي شيء فيه send() يعمل، بوراثة أو بغيرها — وهكذا التقطت FakeNotifier الرسائل في اختبار دون إرسال واحدة. استخدمه للتنفيذات القليلة المحلية البيّنة؛ والجأ إلى الـ ABC حين يفي بالوعد آخرون، أو حين لا يظهر نسيانه إلا في الإنتاج، أو حين يكون هناك سلوك مشترك ليُوزَّع.
